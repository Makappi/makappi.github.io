How to create push campaigns with Make?

  1. FAQ
  2. Integrations
  3. Make

The Make integration lets your Make scenarios create push notification campaigns in your app: a new arrival, a best seller detected from your paid orders, a restock... Each campaign can have an image, open a product, a collection or a link, and be saved as a draft, scheduled or sent immediately.

Campaigns created by Make appear in your Makappi campaign list, like the ones you create yourself. They are sent to every app user who accepted notifications.

The Make integration is available in the Premium and Custom plans. It is enabled by the Makappi team: contact us to activate it.

Step 1: Get your API key

  • In your Makappi dashboard, go to Settings > Integrations > Make
  • Copy the API endpoint and the API key
Keep this key secret: it gives access to your push campaigns. If it leaks, click Regenerate API key: the old key stops working immediately and you will need to update your scenarios.

Step 2: Add an HTTP module in Make

In your scenario, add the HTTP > Make a request module and configure it:

  • URL: https://app.makappi.com/api/v1/push-campaigns
  • Method: POST
  • Headers: name Authorization, value Bearer YOUR_API_KEY
  • Body type: Raw, Content type: JSON (application/json)
  • Parse response: Yes

Then fill the Request content with your campaign, using the data of the previous modules (for example a Shopify product):

{
  "externalId": "new-arrival-8123456789",
  "status": "DRAFT",
  "title": {"en": "New arrival", "fr": "Nouveauté"},
  "message": {"en": "Discover the Blue shirt", "fr": "Découvrez la chemise bleue"},
  "imageUrl": "https://cdn.shopify.com/s/files/.../blue-shirt.jpg",
  "destination": {"type": "PRODUCT", "productId": "8123456789", "productTitle": "Blue shirt"}
}

Campaign fields

  • title and message (required): a text, or one text per language such as {"en": "...", "fr": "..."}. Each user receives their language, or English by default. Title: 200 characters max, message: 1000.
  • status: DRAFT (default, saved without being sent, to review in Makappi), SCHEDULED (sent at sendAt) or NOW (sent immediately).
  • sendAt: sending date in ISO 8601 format, for example 2026-11-02T18:00:00Z. Required with SCHEDULED, must be in the future. The campaign is sent at this exact time for everyone.
  • imageUrl: an https image URL shown in the notification (rich push).
  • destination: what opens when the notification is tapped.
    • {"type": "PRODUCT", "productId": "...", "productTitle": "..."}
    • {"type": "COLLECTION", "collectionId": "...", "collectionTitle": "..."}
    • {"type": "LINK", "url": "https://..."}
    • {"type": "NONE"} (default): opens the app
    Shopify IDs can be numeric (8123456789) or full (gid://shopify/Product/8123456789). Titles are optional and only shown in your dashboard.
  • discountCode: a discount code applied to the cart when the notification is opened.
  • externalId: your own unique identifier for this campaign (see below). Recommended.

Avoid duplicate campaigns

A scenario can run twice on the same data (retry, replay, two triggers). Always send an externalId built from your data, for example new-arrival-{{product id}} or best-seller-2026-11-02. If a campaign with the same externalId already exists, no new campaign is created: the API returns the existing one with "created": false.

Response

A new campaign returns the code 201, an existing one (same externalId) the code 200:

{
  "created": true,
  "campaign": {
    "id": "5f535f0b-4d31-4d17-820c-06411031c114",
    "externalId": "new-arrival-8123456789",
    "status": "DRAFT",
    "title": {"en": "New arrival", "fr": "Nouveauté"},
    "message": {"en": "Discover the Blue shirt", "fr": "Découvrez la chemise bleue"},
    "imageUrl": "https://cdn.shopify.com/s/files/.../blue-shirt.jpg",
    "destination": {"type": "PRODUCT", "productId": "gid://shopify/Product/8123456789", "productTitle": "Blue shirt"},
    "discountCode": null,
    "sendAt": null,
    "deliveryStats": null,
    "createdAt": "2026-10-28T20:13:16.683Z",
    "updatedAt": "2026-10-28T20:13:16.683Z"
  }
}

Keep the id to read, schedule or cancel the campaign later.

Other operations

They use the same URL and the same Authorization header. They only apply to campaigns created through the API.

  • Read a campaign: GET /api/v1/push-campaigns/{id}. Returns its status and, once sent, its deliveryStats.
  • List campaigns: GET /api/v1/push-campaigns, most recent first. Optional filters: ?externalId=..., ?status=DRAFT, ?limit=50 (100 max).
  • Schedule or send a draft: POST /api/v1/push-campaigns/{id}/schedule with {"sendAt": "2026-11-02T18:00:00Z"}, or an empty body {} to send it now.
  • Cancel a campaign: POST /api/v1/push-campaigns/{id}/cancel. A scheduled or sending campaign goes back to draft. Notifications already delivered cannot be recalled.
  • Delete a draft: DELETE /api/v1/push-campaigns/{id}.

Campaign statuses

  • DRAFT: saved, not sent
  • SCHEDULED: waiting for sendAt
  • NOW: queued for immediate sending
  • PENDING: being sent
  • SENT: sent

Errors and limits

Errors return a message explaining the problem: {"error": {"code": "...", "message": "..."}}.

  • 400: invalid field (the message says which one)
  • 401: missing or invalid API key
  • 403: the Make integration is not enabled
  • 404: campaign not found
  • 409: operation impossible in the current status (for example deleting a scheduled campaign)
  • 429: more than 10 campaigns created in one minute
